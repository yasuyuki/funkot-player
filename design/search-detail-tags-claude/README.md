# Liner Proof：検索条件・曲の詳細・タグ編集（#173 Claude 案）

[#173](https://github.com/yasuyuki/funkot-player/issues/173) の試作。[#170 の「Overprint Liner」](../library-general-claude/README.md)（固定コミット `b8b5b15`）を土台に、**検索条件入力・曲の詳細・タグ編集の3領域だけ**を作り直した。製品のソースとデータは変更していない。曲・タグ・ファイルはすべて合成データで、保存はページ内のモックサービスに対して行う。

## 狙い

Liner は、ジャケット裏のライナーノーツのように曲名の活字を主役にした。この案ではその紙面に**校正刷り（proof）**の約束事を足す。

- **検索条件は一文として読む。** 「次の条件に**すべて**当てはまる曲：制作年 2015年 かつ タグ 日本人トラックメーカー かつ ジャンル アニソンremix」。種類は小さな刷りの印（角＝制作年、丸＝ジャンル、荷札＝タグ）と言葉の両方で示す。
- **曲の詳細はクレジットとランアウトの二層にする。** 第一層は聴いて判断するための情報。第二層（畳んである）は、ファイルの場所、内容の識別、埋め込まれたメタデータ、制作年の決め方。レコードの溝の外周に刻まれた情報の位置づけである。
- **タグの未保存の変更は校正記号で示す。** 足すものは桃色の枠と＋、外すものは取り消し線、制作年は「旧 → 新」。保存するまで何も確定しない、と紙面で分かる。

3領域で同じ印・同じ言葉・同じ桃色を使う。条件の行、候補、詳細、編集のどこで見ても「制作年の2015」と「タグの2015」は別物に見える。

## A. 検索条件入力

| 段 | 見えるもの | 押すと開くもの |
| --- | --- | --- |
| 基本 | 検索欄一つ。種類ごとの見出しに分かれた候補。各候補に「N曲になる」と「かつ／または で加わる」。条件は値と × だけ | — |
| 条件ごと | 条件の ⋯ | 別の値も含める（どれか）・一時停止・これを含まない曲にする・外す。**どれも押す前に件数が出る** |
| 全体 | 2条件以上のとき「条件の組み方」 | すべて／どれか。どちらも件数つき |
| 戻す | 一つ戻す・やり直す（Ctrl+Z）、トーストの「元に戻す」、最近の条件 | — |

- **最初の条件を足しても、一時停止・これ以外・または・組み方は出ない。** ベースでは最初の1条件から ⊘・スイッチ・ゴミ箱・「＋または…」が並んでいた（比較で 4 → 0）。
- **取り違えない。** 「2015」と打つと、制作年・タグ・文字が別の見出しに分かれ、「『2015』は制作年とタグの両方にあります」と注意が出る。同名の Funkot もジャンルとタグで別々の候補・件数になる。条件の行は、別の種類に同名の値があるときだけ種類を言葉で添える。
- **何が一致するかを先に言う。** 2つ目の年は「『2015年』または で加わる」と出て、件数はその「または」の結果になる（曲の年は一つなので、年は自動で「または」になる）。ほかは「かつ で加わる」。結果の一覧は、選んでいる候補を仮に足した状態を先に見せる。
- **規模。** 2,600件超のタグは種類ごとに上位3〜4件を出し、「タグをあと N 件見る」で広げる。表記違いは束ねて「表記違いもまとめて含める」で一度に「どれか」にできる。9条件でも条件の行は一行で「ほか N つ」に畳まれ、一覧の開始位置は3条件と同じ。0件のときは「外すと何曲」を出す（ベースのまま）。
- **条件を1つ外す手数を 2 → 1 にした**（desktop、各条件の ×）。条件の語を押すと編集面がその条件の操作を開いた状態で出る。

## B. 曲の詳細

- 行を押すと、その場で開く（ベースと同じ位置）。第一層は 版・アーティスト・長さと形式・制作年と**その由来**・ジャンル・タグ・状態（再生中、再生待ちの何番目、お気に入り、再生回数）。タグは8件まで出し、残りは「ほか N 件」。
- 同名のファイルは形式・長さ・再生回数・フォルダで並べ、「この行」を示す。**中身が同じコピー**は「中身が同じ・タグを共有」と示す。
- 第二層「ファイルと技術情報」に、完全なパス、大きさと更新日、内容の識別（ハッシュ）、ファイルに埋め込まれた項目（TIT2、TDRC、©day などの生の値）、制作年の候補と優先順位、自動の判定（食い違い・読めない値・未来の年）を出す。何も削っていない。
- 詳細の中で Esc を押すと閉じ、フォーカスはその行に戻る。条件と一覧はそのまま。
- 画像・波形・BPM など、いま手に入らない情報は出さない。

## C. タグの編集

- 詳細の「タグを編集」（行で `t` キーでも）で、モーダルの面が開く。desktop は一覧の上に重なる紙、narrow は全画面。背後は操作できず、Tab は面の中を回る。
- **日常の単曲編集は、入力欄一つで終わる。** 打つと種類つきの候補（「タグ コール入り」「ジャンル …」「新しく『X』を作って付ける」）が出て、Enter で付ける下書きに入る。同じ欄が「この曲のタグから探す」も兼ね、一致しないものを薄くする。
- 外すときは各タグの ×。外したタグは消えずに取り消し線で残り、「戻す」で戻る。**「ファイル」と書いた値は音声ファイルから読んだ値**で、外すとこのアプリの分類から除くだけだと説明が出る。以前に外したファイルの値は「外しているファイルの値」に並び、「戻す」で分類に戻せる。
- **多いとき。** 「原曲:」のように同じ接頭辞のタグが4件以上あると「原曲 30件」の束に畳む。46タグの曲でも見える × は20個以下で、入力欄と保存が画面内にある。探せば束の中も出る。
- **制作年は普段は1行**（「2015年 ファイルの日付から ［変える］」）。開くと「ファイルの日付から決める／年を指定する／年なしにする」と、ファイルに入っている日付の一覧（優先順位、元の発売日は自動では使わない、読めない値、食い違い）を出し、候補を押すとその年を指定できる。3桁などは保存できない。
- 下端に未保存の変更の件数と校正記号（＋ − 年）を常に出し、開くと1件ずつ「やめる」ことができる。「音声ファイルは書き換えません」を常に添える。
- **保存は明示。** 成功は「タグを保存しました」、何も変わらなければ「変更はありませんでした。すでに同じ内容です」。保存した値には「保存済み」の印が付き、フォーカスは「タグを編集」に戻る。編集で今の条件から外れた曲は、その場に「いまの条件から外れました」と残る（条件を変えるまで）。
- **キャンセル・Esc・×** は下書きを捨て、トーストの「下書きに戻る」で同じ下書きに戻せる。確認の手数を増やさずに誤操作から戻れる。
- **失敗しても下書きは残る。** 書き込み失敗・読み取り専用・処理中は理由とコードを出し、「もう一度保存」。
- **stale_revision。** 開いている間に別の操作やスキャンで版が変わると、保存の前に知らせて保存を止める。「最新の内容を読み込む」で、何が変わったか（「ほかの操作で タグ『コール入り』が加わっていました」）を出し、下書きはそのまま残す。同じ変更がすでにある下書きは「下書きの追加は不要に」と示し、保存すると no-op になる。
- **identity_changed。** ファイルの中身が変わったら、下書きを新しいファイルには保存しない。「新しいファイルで開き直す」と、前の下書きと、前の内容に付けていて引き継がれなかった手動タグが「入れる」付きで並び、押したものだけが入る。
- **まとめて編集。** 「まとめて選ぶ」の帯に「タグを編集」を足した。対象は開いた時点で**表示されていて保存できる曲**に固定し、隠れた曲・ファイルの無い曲は理由つきで外す。中身が同じファイルはデータを共有するので「対象 3曲・保存するデータは2つ」。タグは「3/3」「2/3」と読め、混在は斜線の地。混在タグは＋で全曲に付け、× で全曲から外す。制作年は既定で「変更しない」。

### 守っている意味（[docs/track-tags.md](../../docs/track-tags.md)）

- 要求は `update_track_tags` と同じ形（targets＋expected_hash、expected_revision、patch の add / remove / year_change）。add / remove は差分で、全体の置換はしない。
- 年は「変更しない（省略）・auto・set・unset」を区別する。手動の年が自動より優先。自動の年は録音日 → 日付 → 発売日の優先順で、上位の不正・未来・食い違いは下位で隠さない。
- 手動の記録は内容のハッシュに属し、重複ハッシュは一つの記録を共有する。応答の changed / no_op はハッシュ単位で数える。
- 埋め込みのタグを外すと suppression になり、ファイルは変えない。試作では音声ファイルを表すオブジェクトを凍結し、検証で全曲の値が保存の前後で変わらないことを確かめた。

## 接続部分として変えたところ（3領域の外）

| 場所 | 変更 | 理由 |
| --- | --- | --- |
| 条件の行（検索欄の下） | 条件ごとに × を付け、行末の「すべて外す ×」を除いた（すべて外すは編集面とBackspaceに残る）。narrow は × を出さない | 条件を1つ外すのを1手にするため |
| 「まとめて選ぶ」の帯 | 「タグを編集」を足した。narrow ではボタンが入りきらないため帯を2段にした（1段目：選択数・表示中を選択・やめる、2段目：タグを編集・追加） | 一括編集の入口 |
| 行 | キーボードの `t` でタグ編集を開く | 入口の近道 |
| 詳細の操作 | 「タグを編集」を追加先のボタンの隣に移した | 編集の入口を詳細の主な操作にするため |

一覧の行、ナビ、再生バー、追加先ドック、テーマはベースのまま。一覧の最初の行の位置はベースと同じ（下の表）。合成データには手置きの曲を2つ足した（中身が同じコピーと、46タグのメガミックス）。曲数は 24,825（ベース 24,823）で、3条件の件数は 53 → 55 になる。追加先の中身はベースと同じ曲になるよう合わせた。

## 検証

`verify.mjs` が実際のマウス・キーボード・タッチ入力で確かめる。直近の実行で **87/87** が通った（[verify-result.json](verify-result.json)）。

- A：初期状態で条件の行が出ない。「2015」で制作年とタグが別の見出しに分かれ注意が出て、Enter で制作年の条件が入る。最初の条件の直後に高度な操作が0。ローマ字 anison でジャンルが出る。候補の件数・「かつ／または」の予告が、選んだ後の結果と一致する。条件の × とトーストの取り消し。語から条件の操作を開き、一時停止の予告件数と実際が一致。戻す・やり直す。2つ目の年は「または」。すべて／どれか の件数が一致。同名の Funkot がジャンルとタグで別。9条件が一行で畳まれ一覧の位置が変わらない。0件の緩和。
- B：第一層の項目と年の由来。第二層が最初は畳まれていて、開くとパス・識別・TIT2/TDRC・年の決め方。Esc で閉じ行へフォーカス。食い違う年の理由。中身が同じコピー。
- C：モーダル・入力欄へのフォーカス・背後が操作不可・Tab が出ない。種類つき候補と Enter。ファイル由来の値を外す説明。保存の要求が差分（add/remove）で、手動の記録だけが変わり、埋め込みの値は残る。保存後も開いた曲が残りフォーカスが戻る。キャンセルと「下書きに戻る」。書き込み失敗で下書きも記録も変わらず、再試行で保存。開いている間の更新で保存を止め、読み込みで差分を出し下書きを保つ。保存時の stale_revision から no-op。identity_changed で新しいファイルに保存せず、開き直しで「入れる」を押したものだけが入る。年の「年なし」「指定」「3桁は不可」「候補から指定」と保存。46タグで × が20以下・入力と保存が画面内・束の中も探せる。Ctrl+Enter。一括編集の対象（隠れた曲・ファイルの無い曲を除く）、データ2つ、2/3、年は変えない、スキャン中も対象固定、要求と応答の単位。**保存・失敗・競合・一括を通して音声ファイルを表すデータが変わらない。**
- 読み上げ名：8つの状態で見えている操作すべてに名前がある。
- narrow（412×915、タッチ）：全画面シート、シートと結果画面の操作が44px以上、シートの中も横にあふれない、詳細・編集・多タグ・一括・年・失敗・開き直しで横あふれなし・44px以上・保存が画面内、タップだけで外して保存。
- 200%（640×450）：検索・詳細・編集・多タグ・一括で横あふれなし、入力欄と保存が画面内。

目視で直したもの：狭幅で編集面の格子がずれフッターが伸びた。狭幅で条件の編集面が全画面にならなかった。46タグで × が46個並んだ（束ねた）。再読込の後、不要になった下書きが「追加」と「ほかの操作で追加」の両方に見えた。狭幅の制作年の棒が18px幅だった（44px で横スクロールにした）。候補の列と詳細の一覧のクラス名が衝突し、狭幅のシートが横にあふれた。

## 動かし方

`index.html` をブラウザで直接開く。サーバーは要らない。書体の読込みにはネットワークが要る。右下の帯はデモ用で製品の UI ではない。状態を選ぶほか、**次の保存を失敗させる（書込失敗・読取専用・処理中・競合）**、**別の操作で更新**、**ファイル差替**、**スキャン**を起こせる。`?s=<状態名>` で同じ状態を開ける（`base` `a` `a-first` `a-type` `a-amb` `a-funkot` `a-menu` `a-or` `eight` `eight-edit` `zero` `long` `detail` `detail-tech` `detail-moon` `detail-copy` `edit` `edit-open` `edit-sugg` `edit-year` `many` `many-find` `batch` `batch-year` `batch-scan` `fail` `stale` `stale-reloaded` `identity` `identity-reopen` `saved`）。

一通りの流れ：`?s=base` → 検索欄に「2015」→ Enter →「日本人」→ 候補 →「anison」→ 候補 →「55曲を表示」→ 放課後シグナル（MP3）を開く →「タグを編集」→「コール」Enter → アニソンremix の × →「保存」→ 条件の語や × で検索へ戻る。

```
node capture.mjs <node_modules/playwright のパス>   # shots/ を作り直す
node verify.mjs  <node_modules/playwright のパス>   # 操作の検証（verify-result.json）
node compare.mjs <node_modules/playwright のパス>   # ベースとの比較（compare/）
```

## 未検証のこと

- Android 実機、WebView2、ソフトキーボードが出た状態。編集面の下端がキーボードの上に残るかは確かめていない。
- スクリーンリーダーの実際の読み上げ。確かめたのは読み上げ名の有無と内容だけ。
- ブラウザの文字だけ 200% の設定。確かめたのはページ全体の 200% に当たる 640×450。
- 永続化・Native の保存・ファイル保護。試作の保存はページ内のモックで、ファイル保護は「凍結したオブジェクトが変わらない」ことの確認に留まる。
- 2,600件・24,825曲での照合の速さを製品の実装で測っていない。候補の件数は入力ごとに全曲を照合している（試作の desktop では遅れを感じない範囲）。

## 判断が残る点

1. **条件の行の × は desktop だけ。** narrow は1行に入らないため出さず、外すのは2手のまま。
2. **詳細の完全なパスを第二層に移した。** フォルダは同名ファイルの欄に出るが、完全なパスは＋1手。
3. **キャンセル・Esc は確認せずに捨て、トーストで戻せるようにした。** トーストの6秒を過ぎると下書きは戻らない。
4. **接頭辞の束は「:」で4件以上から。** 規則で畳むので、接頭辞を使わない運用では束ができない。
5. **年を2つ選ぶと自動で「または」になる。** ほかの種類で「または」にするには条件の ⋯ から「別の値も含める」を選ぶ。予告は出るが、この非対称が分かりやすいかはユーザーの目で判断してほしい。
6. 製品にない追加の要求：保存後に開いた曲を残すには保存の応答の後で一覧を並べ直さないことが要る。identity_changed の開き直しで前の手動タグを示すには、前のハッシュの手動記録を読む手段が要る。

# Overprint Index：検索条件入力・曲詳細・タグ編集の改善案（#173 agy）

[Issue #173](https://github.com/yasuyuki/funkot-player/issues/173) に基づき、[Claude「Overprint Liner」](../library-general-claude/README.md)（固定コミット `b8b5b15d5800e44f49e78ec4bf40309a94ed443a`）をベースとして、**A. 検索条件入力／B. 曲の詳細情報表示／C. タグ編集** の3領域だけを再設計した独立試作である。

- ブランチ: `proposal/173-agy`
- 対象外領域（上端タブ、ライブラリ一覧行の2行構造、追加先ドック、下端再生バー、配色・書体・リソグラフの版ずれ質感）は Overprint Liner をそのまま維持している。
- 製品本体（`src/`、`src-tauri/`）と `design/library-general-claude/` は変更していない。データはすべて決定論的な合成データ（24,823曲・2,678タグ索引）と `docs/track-tags.md` 契約を模したメモリ内 `MockTagService` で構成している。

## 設計原則と強みの活かし方

**「普段の見た目と手数は静かなまま、条件・情報・編集状態が膨らんでも構造が崩れない」**ことを軸にした。

1. **段階的開示（一般向けと高度操作の分離）**: 最初の検索入力・1件目の条件追加では「すべてに一致／どれかに一致」「一時停止」「これ以外」「＋または」などの高度な論理操作を一切見せない。条件を整理したいときだけ全幅の「条件整理台帳（Condition Ledger）」へ切り替える。
2. **背景一覧の幾何安定**: 検索パレットをデスクトップではフローティング面として入力欄直下に重ね、曲詳細は一覧右側のインスペクターペインへ分離した。これにより条件入力中や詳細閲覧中も、一覧の開始位置（`218px`）や隣接曲の行位置が上下に跳ねない。
3. **現実のデータ契約の忠実な保持**: `src/lib/tauri.ts`・`src-tauri/src/tag_service.rs`・`src-tauri/src/track_tags.rs`・`docs/track-tags.md` に沿い、種別キー（`year` / `genre` / `custom`）・表記揺れ・音声ファイル非書換・同一 `content_hash` 共有・選択対象固定・`stale_revision` 復旧・`identity_changed` 拒否をすべて動く試作として実装した。

## 3領域の設計

### A. 検索条件入力（静かなパレット ＋ 全幅の条件整理台帳）
- **初期検索・1〜2条件時**: 「候補から追加」モードのみを開き、高度操作ボタンを0個にする。`2015` 入力時は `制作年: 2015`・`任意タグ: 2015`・`曲名・アーティストに「2015」を含む` を種別バッジと注意帯で明瞭に区別する。
- **2,600+タグと表記揺れの扱い**: 候補種類タブ（`すべて / 制作年 / ジャンル / 任意タグ / 曲名・アーティスト`）、折り畳み表記揺れバンドル（例：`アニソンremix` + `anison remix` + `アニソンリミックス` をまとめて「どれか」で追加）、`さらに候補を表示` ページネーション、追加後のヒット数予測（`加えると N曲`）を備える。
- **全幅の条件整理台帳（9条件も非スクロール表示）**: 条件をクリックするか「条件を整理」を押すと、左右分割をやめてパレット全幅を条件整理台帳として使う。上端に自然文プレビューと一括操作（AND/OR切替、`制作年が未設定（常にAND）`、停止中一括再開、Undo/Redo）を置き、デスクトップ 1280×900 では **9条件すべてをスクロールなし（`9/9` 行、`lensScrollable: false`）** で俯瞰・編集できる。
- **0件時の原因診断と「一時停止して試す」**: 異なる年のAND指定や年未設定との矛盾を検出し、条件を消さずに試せる `一時停止` ボタンと `外す`・`ORへ切替` を並べる。

### B. 曲の詳細情報表示（3層の Liner Inspector）
- **第1層（聴く・判断する）**: 全曲名と版/リミックス表記（切り詰めなし）、アーティスト（未記録時は明示）、制作年（自動／手動／未設定固定／競合・未来年・不正警告＋候補誘導）、長さ・形式、再生回数、保存フォルダ、追加・お気に入り・追加先変更ボタン、ジャンルと任意タグ（クリックで条件追加）。32件のタグがある曲では先頭10件＋「残りN件を表示」＋インライン絞り込みで縦破綻を防ぐ。
- **第2層（同名ファイル・コピーの区別）**: 同一楽曲の別形式・別ファイル（MP3/FLAC 等、異なる `content_hash`）と、同一データのコピー（同じ `content_hash` で手動タグ共有）を分けて表示し、版ごとの表示切替や直接追加を行える。
- **第3層（ファイル・メタデータ詳細 `<details>`）**: 通常時は折り畳み、問題があるときだけ「注意あり」を表示。開くと未省略のフルパス＋コピーボタン、`content_hash`、解析状態、埋め込み年候補と採否理由（`TYER` / `TDRC` / `DATE` / `©day` / `TDOR`）、タグの由来（`embedded / manual / both`）、除外済み自動タグ、診断メッセージを確認できる。`Esc` または `×` で閉じると元の行ボタンへフォーカスが戻る。

### C. タグ編集（日常最速・大規模対応・安全境界）
- **日常の単曲編集の最短経路**: モーダル最上部に曲名・対象範囲と「音声ファイル自体は書き換えません」を置き、制作年（単曲は現在のモード、複数は必ず「変更しない」で開始）と、ジャンル／任意タグ切替付きのオートコンプリート入力欄を最優先に配置。10件以下は軽快なチップ、11件以上または複数曲一括では検索・種類タブ（`すべて / ジャンル / 任意 / 変更`）付きの固定高さ台帳へ切り替わり、常に保存／キャンセルのフッターが画面内に固定される。
- **年候補・除外・複数一括**: 年の競合／未来／不正状態では埋め込み候補から有効年を1クリック採用でき、未来年・不正年は選択不可として理由を示す。自動ジャンルの削除は「除外（再スキャン後も自動付与しない）」として扱い、除外済み一覧から1クリックで復元できる。複数一括では同一 `content_hash` の統合件数（例：3行→実データ2曲分）とフィルタ外選択の非対象を明示し、混在タグに対して「全曲に追加」「全曲から外す」の両方を提供する。
- **競合・安全性**: `stale_revision` 発生時は下書きと入力年を保持したまま `最新を再読込` を提示し、対象ハッシュの一致確認後に下書きを維持して再保存できる。`identity_changed` では別の曲への誤適用を防ぐため `保存` を無効化し、`store_read_only` では閲覧のみ許可する。保存後の変化有無（`changed` と `no_op`）は通知文とリビジョン番号で区別する。

## 試作の使い方・検証コマンド

`index.html` をブラウザで直接開く。右下のデモバー、または URL `?s=<状態名>`（`base`, `search-basic`, `search-disambig`, `a`, `eight`, `eight-manage`, `zero`, `year-unset`, `detail`, `detail-tech`, `detail-many`, `edit-single`, `edit-many`, `edit-year-conflict`, `edit-bulk`, `edit-conflict`, `edit-identity`, `edit-readonly`, `a-select`, `loading`, `error`）で各状態へ直接遷移できる。

```sh
node verify.mjs  <path-to-node_modules/playwright>   # 39項目の操作・契約・狭幅/拡大検証 (verify-result.json)
node capture.mjs <path-to-node_modules/playwright>   # Desktop / Dark / Narrow / 200% の画面撮影 (shots/)
node compare.mjs <path-to-node_modules/playwright>   # Claude Liner との同条件比較 (compare/)
```

## 検証結果と目視による修正

- `verify.mjs` 実行結果：**39/39 合格**（[verify-result.json](verify-result.json)）。24,823曲すべての `embedded` スナップショット非改変（`verifyAudioFilesUntouched().ok === true`）、`stale_revision` 保持復旧、`identity_changed` ブロック、狭幅（412×915）の全操作要素 ≥44px・横あふれゼロ、200%拡大（640×450）での操作到達性を自動確認済み。
- 実画面の目視レビューで以下を発見し修正した：
  1. 狭幅・200%拡大の曲詳細（`.inspector`）の下端に再生バー（`.now`）が重なっていた → `.app.inspector-open .main { z-index: 45 }` を追加して解消。
  2. デスクトップ詳細表示時、左一覧の「まとめて選ぶ」が2行折り返し、詳細ヘッダに不要な `←` アイコンが出ていた → 右ペイン幅調整・`white-space: nowrap`・デスクトップでの `.insp-back` 非表示で解消。
  3. 9条件整理台帳で「曲名・アーティスト」列幅が狭く切れており、9行目の下端が少し欠けていた → 種類列を `124px` へ広げ、パレット高さと余白を調整して **9条件すべてを非スクロールで完全表示**。
  4. 狭幅タグ編集の追加欄プレースホルダー切れとボタン折り返し → 狭幅時のみ種別切替を上段に分け、入力欄と「追加」を2段目で横並びに固定。

## 正直な未検証範囲・限界

- **ブラウザ試作の限界**: Android 実機・実機上のソフトキーボード表示時のレイアウト変化、Windows WebView2 固有描画、スクリーンリーダー（NVDA / TalkBack）の実音声読み上げ、実際の Rust/Tauri 永続化・音声ファイル読取は未検証（本試作はブラウザ上のモックによる UI・状態設計検証である）。
- 200%拡大は CSS viewport `640×450` 相当で検証しており、OS／ブラウザの文字サイズ単体200%設定時の細部挙動は製品実装時に確認が必要。

# Overprint：音楽ライブラリ UI の白紙設計（#169 Claude Code 案）

[#169](https://github.com/yasuyuki/funkot-player/issues/169) への独立提案。#168 の各案と現行 UI の画像・CSS・コンポーネント構造は参照していない。製品ソースは変更しない。

## 体験の狙い

同人イベントで自主制作のリミックス CD を掘り当てるときの高揚感を、画面の質感に置き換える。リソグラフ印刷のジャケットやフライヤーのように、蛍光ピンクと青の二色インクを冷たい紙色に刷った見た目にする。

大胆に使う場所は一つだけにした。**検索条件を「刷られたスタンプの文」として見出しに置く**ことである。

> **［2015年］** かつ **［日本人トラックメーカー］** かつ **［アニソンremix］**　　**53** 曲

ほかの要素はこれに従い、静かにまとめた。曲の行はインクを使わず、曲名の太さと大きさで読ませる。追加操作は細い輪郭だけにする。

## 情報の構造

```
┌ナビ┬ 条件の文（スタンプ）……………………… 件数 ┬ 追加先 ─────────┐
│    │ [ 曲名、アーティスト、タグ、年で探す   / ] │ ■ 再生待ち          │
│    │ ┌ 条件を組み立てる（入力中だけ開く）┐    │ 追加先の切替        │
│    │ │ いまの条件 │ 候補・年の棒・タグ   │    │ 末尾の曲（追加結果）│
│    │ └────────────────────┘    │ ─ここから自動選曲─  │
│    │ 曲名（主役）                 年 長さ ⊕ │                     │
│    │ アーティスト  一致したタグ              │                     │
├────┴────────────────────────────┴─────────────────────┤
│ 再生中の曲　再生元：再生待ち　次の曲                 ‖  ▶|                 │
└───────────────────────────────────────────────────────────┘
```

narrow（412px）では、追加先が下端のバーになり、条件の組立ては全画面のシートになる。

| 優先 | 担う場所 | 決め方 |
| --- | --- | --- |
| ①発見・高度な検索 | 条件の文、一つの検索欄、条件のパネル | 入力は一欄だけ。候補には種類（制作年・ジャンル・タグ・アーティスト・曲名の文字）と「加えると何曲になるか」を出す |
| ②曲名による判断 | 結果の行、行を開いた詳細 | 曲名 18px 太字を最大にする。版の表記（Remix など）は細字に落とす。同名ファイル、曲名の欠け、アーティストの欠けは行内で区別する |
| ③正しい追加先へ追加 | 行末の ⊕、右の追加先 | ⊕ の色は追加先の色と同じにする。追加先の名前を常に表示し、追加した項目が落ちた位置も見せる |
| ④音楽アプリの魅力 | 条件の文、紙とインクの質感 | 二色インクのずれた刷り、紙の粒子、Dela Gothic One の見出し |
| ⑤整理・タグ編集 | 行を開いた詳細 | 常設のボタン列は置かない。タグを押すと検索条件になる |

### AND と OR の表し方

* 条件どうしの間には、文として「かつ」を印字する。上部の「3つの条件の **すべて** に一致する曲」を押すと「どれか」に切り替わる。そのとき間の語も「または」に変わる。
* 一つの条件の中に「または」で値を並べられる（例：［アニソンremix または 電波remix］）。OR は必ず一枚のスタンプの中に閉じるので、優先順位の誤読が起きない。
* 制作年は一曲に一つしかない。そのため、年を二つ選ぶと自動で同じ条件の「または」に入る。0 件になる AND は作らない。
* 条件の種類はスタンプの形で示す。制作年は角、ジャンルは丸、タグは荷札の切り欠き、曲名の文字は黄色。
* 各条件は、一時停止（点線になって結果から外れる）、「これ以外」（取り消し線）、削除と取り消しができる。最近使った条件の組は一操作で戻せる。

### 数千のタグから選ぶ

* 一つの欄に入力すると、種類をまたいで候補を出す。ローマ字・ひらがな・カタカナの違いと記号は揃えて照合する（`anison` → アニソンremix）。
* 並び順は、前方一致を先にし、次にライブラリでの曲数の多い順にする。各候補には「加えると N 曲」を出し、0 曲になる候補は薄く表示する。
* 正規化すると同じになる別表記（アニソンRemix、anison remix、アニソンリミックス）は一行にまとめる。「表記揺れをまとめて『どれか』で加える」も選べる。
* 入力していないときは、年の棒グラフ、いまの結果に多いジャンル、いまの結果に多いタグを出す。どれも件数はいまの条件で数える。候補を延々とスクロールさせず、入力するか、いまの結果から選ぶかの二通りで目的のタグに届くようにした。
* 入力中、結果の一覧は「選択中の候補」を仮に適用した状態を示す。ヘッダーには点線のスタンプが出る。生の文字列では絞らない。そのため、タグ名を途中まで打った時点で一覧が 0 件になることはない。

### 追加

* 行末の ⊕ は、触れる範囲が 52px、描く円は 30px の輪郭だけにした。曲名の面積はその約 14 倍ある（検証 C8）。行に触れるか、フォーカスが来たときだけ塗りつぶす。ホバーしなくても輪郭は常に見えている。
* 一回押すと追加される。トーストで「〈曲名〉を再生待ちの5番目に追加しました」と伝え、取り消しも出す。右の追加先では、入った項目が強調される。再生待ちに入れた曲は、自動選曲の境界より前に入る。
* 追加先を変えると、⊕ の色と読み上げラベル（「〈曲名〉を金曜の夜に追加」）が変わる。お気に入りを選ぶと ⊕ は ♡ に変わり、もう一度押すと登録を外す。お気に入りは一曲につき一度しか登録できない。
* 再生元（いま再生しているリスト）と追加先は別に表示する。下端の再生バーは「再生元」を示し、追加先の一覧では再生元に「再生中」の札を付ける。
* まとめて選ぶ場合：「まとめて選ぶ」を押す。キーボードなら Space で選ぶ。そのあと、上のバーの「〈追加先〉に追加」で一度に入れる。
* キーボード：`/` で検索欄へ移る。↑↓ で候補を移り、Enter で確定する。空の欄で Backspace を押すと最後の条件を外す。結果の行では ↑↓ で移動し、`A` で追加する。Esc で閉じる。

## 規模と例外

| 状況 | 画面 |
| --- | --- |
| 24,823 曲、2,600 件超のタグ | 合成データを実際に生成して照合している。一覧は 60 行ずつ追加で描画する |
| 8 以上の条件 | 見出しの文は 2 行までにし、残りは「ほか7つ」の一枚に畳む。条件の編集は左列で縦に並べてスクロールする。開いている間は見出しの文を隠し、結果の一覧を残す |
| 長い曲名・長いタグ | 一覧では 1 行に省略する。行を開くと全文を折り返して表示する。スタンプは 20em（narrow では 9em）で省略し、読み上げラベルには全文を入れる |
| 重複曲 | 黄色の「同名2件 MP3」を行に付ける。詳細では形式・長さ・場所・再生回数を並べ、ファイルごとに追加できる |
| メタデータの欠け | タイトルが無い曲はファイル名を斜体で示す。アーティストが無い曲は「アーティスト情報なし」と示す。制作年が無い曲は「—」とし、年の棒グラフの下に件数を出す |
| 結果 0 件 | 一つ外すと何曲になるかを並べる。一つでは足りなければ二つの組合せを出す。「どれかに一致」に切り替えた場合の件数も出す |
| 検索中 | 件数を「…」、行を骨組み表示にし、「24,823曲を照合しています」と出す |
| 失敗 | 赤の帯で原因と「再試行」を示す。一覧と件数は前回の結果を薄く残し、「曲（前回の結果）」と明記する |
| ファイルが無い曲 | ⊕ を灰色にし、押すと理由を伝える。行と詳細に「ファイルが見つかりません」と出す |
| 文字 200% | 1280×900 を 200% にすると 640×450 相当になり、narrow の配置に切り替わる。条件の組立てはシートで行える |

## 試作の使い方

`index.html` をブラウザで直接開く。サーバーは要らない。書体の読込みにはネットワークが必要である。右上の「デモ」は状態を切り替えるためだけの帯で、製品の UI ではない。`?s=<状態名>` でも同じ状態を開ける。

```
node capture.mjs <node_modules/playwright のパス>   # shots/ を作り直す
node verify.mjs  <node_modules/playwright のパス>   # 流れ A〜D を実際の入力で確認する（30項目）
```

`verify.mjs` が確かめる流れは次のとおり。(A) 候補から 2015年・日本人トラックメーカー・アニソンremix を選んで AND を作る。(B) 一時停止・再開・削除・取り消し・「または」を加える。(C) 1 クリックで追加する、追加先を変える、ファイルの無い曲を拒否する、キーボードで追加する、まとめて追加する。(D) 412px のタッチで同じ作業を行う。

## 現行案と根本的に違う点

* 検索が「入力欄とタグの select」ではない。条件そのものを画面の主役の文にした。AND と OR を言葉と形で読み分けられる。
* ボタンの列を置いていない。行の操作は ⊕ 一つだけで、二次操作は行を開いた中にある。ナビは同じ寸法のアイコンと短いラベルで揃えた。
* 追加先を画面の固定の場所に持たせた。どこに入るか、どこに入ったかが、押す前にも押した後にも見える。

## 後続実装検討事項（設計の水準は下げない）

既存のデータで成り立つもの：制作年・ジャンル・タグ（`TrackTagState`）、タイトル・アーティスト・長さ・パス（`TrackRow`）、再生回数、お気に入り、プレイリスト、再生待ちの手動と自動の境界、再生元。候補の件数と、いまの結果に多いタグは、既存のタグの snapshot から数えられる。

新しいデータや機能が要るもの：

* **表記揺れの統合**：いまは表示の時点で正規化して束ねているだけである。恒久的に一つのタグへまとめる操作と別名の保存は、タグ保存形式の変更になる。
* **漢字の読みでの照合**：かなとローマ字の揃えは試作で実装した。漢字の読みで引くには読みのデータが要る。
* **最近の条件の保存**：試作ではセッション内だけで持つ。
* **タグの分類（任意タグのグループ）**：いまの種類は制作年・ジャンル・任意の 3 つである。「原曲:」のような接頭辞を分類として扱う設計は、別途提案できる。試作では前提にしていない。
* **大規模な照合の速度**：検索中の表示は設計済みである。実際の索引方式は採用後に調べる。

# Overprint Liner：一般向けライブラリ UI の統合案（#170）

[#170](https://github.com/yasuyuki/funkot-player/issues/170) の試作。[#169 の Claude 案「Overprint」](../library-ideal-claude/README.md)を土台に、Codex・Cursor・agy の案から要素を選び直して一つの案にまとめた。製品のソースとデータは変更していない。曲・タグ・アーティストはすべて合成データである。

## 狙い

Overprint は、リソグラフの二色インクで検索条件を大きなスタンプとして刷った。この案ではその質感を残したまま、**ジャケットの裏に刷られたライナーノーツ**の組み方に変えた。主役は曲名の活字にする。蛍光ピンクは小さな印にだけ使う（条件の種類を示す印、条件語の下線、再生中、選択中のタブ）。版ずれは件数の数字と印に残した。

画面を開いた直後に分かることは次の四つである。

| 問い | 答える場所 | 常に見えるか |
| --- | --- | --- |
| 何を探せるか | 検索欄一つ（「曲名・アーティスト・タグ・年で探す」） | 見える |
| どの曲があるか | 件数と曲の一覧（曲名 19px、狭幅 17.5px） | 見える |
| 選んだ曲がどこに入るか | desktop は右の「追加先」、narrow は一覧の上の追加先チップ。＋の色は追加先の色 | 見える |
| いま何が再生中か | 下端の再生バー（再生元つき）、一覧の行の印と曲名の色 | 見える |

## 段階的に開く

機能もデータも削っていない。既定画面に出すものを減らし、必要なときに開く。

| 層 | 常に見える | 押すと開く |
| --- | --- | --- |
| 検索 | 検索欄、条件の一行（条件があるときだけ）、件数 | 条件の編集面（候補、件数予測、年の棒、多いジャンルとタグ、表記揺れ、すべて/どれか、一時停止、これ以外、言い換え、最近の条件） |
| 曲 | 曲名、アーティスト、年、長さ、同名の印、状態（ファイルなし・追加先にあり） | 行を押すと詳細（全タグ、制作年の由来、ファイル、再生回数、同名ファイルごとの追加、お気に入り、タグ編集、ほかの追加先へ） |
| 追加 | 行末の＋（追加先の色）、追加先の名前 | 追加先の一覧（desktop は「変える」、narrow はチップ）、まとめて選ぶ（narrow は並び順と同じメニュー） |
| その他 | 3つのタブ | ⋯（再生の履歴、テーマ、設定） |

### 条件の一行

- 条件は一行に印刷する。各条件は「種類の印＋下線の付いた語」で、間に「かつ」または「または」を置く。印の形は Overprint のスタンプの形を小さくしたもの（制作年は角、ジャンルは丸、タグは荷札の切り欠き、文字は黄色）。
- 一行に入らない条件は「ほか N つ」に畳む。9条件でも行の高さは変わらず、曲の一覧の開始位置も 3 条件のときと同じである。
- 語を押すと編集面がその条件を指して開く。「編集」で全体を開き、「×」で全部外す（取り消しと最近の条件で戻せる）。
- 一時停止中の条件は点線、「これ以外」は取り消し線で、一行の中でも区別できる。
- 編集中はこの一行を隠し、編集面だけを見せる。編集面の下端に「条件を編集中」「すべて外す」「N 曲を表示」を置き、閲覧と編集を見分けられるようにした。
- すべて/どれか の切替は編集面の上部にある。0件のときは結果の位置にも「どれかに一致する曲にする（N 曲）」を出す。

### 行

- 2行に収める。1行目は曲名（版の表記は細字で小さく）、2行目はアーティスト・年・長さ・同名の印・状態。
- 「すべて」のときはどの行もすべての条件に一致するので、一致したタグを行に繰り返さない。「どれか」のときだけ、どの条件で一致したかを2行目に出す。
- ＋は線一本の記号で、ホバーやフォーカスで輪郭が付く。描く記号は 18px、押せる範囲はマウスで 40px、タッチで 48px。
- 追加すると、その行の＋が ✓ になり、2行目に「✓ 再生待ちの5番目」と出る。トーストで取り消せる。desktop では右の「末尾の曲」に入った位置が強調される。

読み方と注意：

- 行あたりの操作は両案とも2（行を開く、＋）。＋の見た目は 30px の輪郭付き円から、輪郭のない 18px の記号に変えた。
- ナビは desktop で 5 → 4（縦のレール4項目とテーマ → タブ3つと⋯）。narrow は 0 → 4 である。元案は狭幅でレールを隠し、ライブラリ以外の画面へ移る手段が無かった。この案ではタブ3つと⋯を上端に置いたため、数としては増えた。
- desktop の条件編集中は、一覧の上端が 454 → 508 px に下がる。編集面の下端に「N 曲を表示」と「すべて外す」の帯を足したためである。編集中の主役は候補なので、許容と判断した。
- narrow の条件編集は両案とも全画面のシートなので、一覧の行数は 0 である。
- narrow の曲名の幅は変わらない（330 px 前後）。narrow で増えた行数は、行を3行から2行に減らし、条件と追加先を上部の2行に収めたことによる。

### 主な操作の手数（同じ状態から数えた）

| 操作 | 元案 | この案 |
| --- | --- | --- |
| 1曲を追加 | 1（＋） | 1（＋） |
| 追加先を変える（desktop） | 1（右の一覧） | 2（「変える」→ 選ぶ） |
| 追加先を変える（narrow） | 2 | 2（チップ → 選ぶ） |
| 条件を1つ外す（desktop） | 1（スタンプの×） | 2（語 → 編集面の削除）、全部なら1（×） |
| 条件を1つ外す（narrow） | 2 | 2 |
| すべて/どれか を切り替える | 1 | 2（編集 → 切替） |
| 外した条件を戻す | 1（取り消し）または最近の条件 | 同じ |

追加先と一致のしかたは、変える頻度が追加より低い。そこで一段奥に入れ、常設の操作を減らすことを優先した。desktop で条件を1つ外す手数が増える点は、判断が残る点として下に記す。

## 検証

`verify.mjs` は実際のマウス・キーボード・タッチ入力で次を確かめる。直近の実行で 46/46 が通った（[verify-result.json](verify-result.json)）。

- 初期画面：条件の一行は出ず、検索欄の下から一覧が始まる。
- A：`/` で検索欄。「2015」で制作年の候補、「日本人」で複数の候補、ローマ字「anison」で アニソンremix と表記揺れが出る。3条件の AND を作り、編集面は別の面として開き「N曲を表示」で閉じる。条件は一行（48px 以下）の3語になる。
- B：語から編集を開く。一時停止で結果が広がり、再開で戻る。削除して取り消すと同じ位置に戻る。「どれか」で結果が広がり、間の語が「または」になる。Esc で編集面が閉じ、フォーカスが検索欄へ戻る。× で全部外して取り消す。全部外したあと最近の条件から同じ件数に戻す。
- C：＋の読み上げ名が追加先を含む。1クリックで再生待ちの N 番目に入り、行とトーストと右の末尾に出る。追加先の一覧は畳まれていて、「変える」で開く。金曜の夜に変えると＋の読み上げ名も変わる。ファイルの無い曲は追加できず理由が出る。↓ と A で追加できる。＋の記号の面積は曲名の 1/10 未満で、押せる範囲は 28px 以上である。
- E：9条件でも条件は一行で「ほか N つ」に畳まれ、一覧の開始位置は 3 条件と同じ。「ほか N つ」で9条件の編集面が開く。
- D（412×915、タッチ）：検索欄のタップで全画面シート。3条件をタップで作り、件数ボタンで閉じる。横あふれが無い。1タップで追加する。追加先チップから5つの追加先を開いて切り替える。シートで条件を外す。シートの操作はすべて 44px 以上。結果画面に見えている操作もすべて 44px 以上。
- Z：1280×900 を 200% にした 640×450 で横あふれが無く、最初の行とその＋が画面内にある。
- N：見えている操作すべてに読み上げ名がある。行は「曲名、アーティスト」と読む。

画面は `shots/`（desktop、narrow、200%、暗色）にある。状態は通常、3条件、候補の一覧、入力中、追加直後、詳細、どれか、9条件、9条件の編集、0件、検索中、失敗、長い名前、追加先の一覧、まとめて選ぶである。目視では次を確認し、直した。

- narrow で検索欄が列からはみ出していた。
- 9条件の一行で、語が縮んで重なっていた。「ほか N つ」に畳むよう直した。
- narrow のトーストが曲名の途中で切れていた。2行まで出すようにした。
- Esc で編集面を閉じると、フォーカスが戻った検索欄が編集面を開き直していた。
- 編集面のタッチ操作の一部が 34〜42px だった。

## 試作の使い方

`index.html` をブラウザで直接開く。サーバーは要らない。書体の読込みにはネットワークが要る。右下の「デモ」は状態を切り替えるための帯で、製品の UI ではない。`?s=<状態名>` で同じ状態を開ける（`base`、`a`、`a-browse`、`a-edit`、`added`、`a-detail`、`a-or`、`eight`、`eight-edit`、`eight-dest`、`zero`、`loading`、`error`、`long`、`a-dest`、`a-select`）。

```
node capture.mjs <node_modules/playwright のパス>   # shots/ を作り直す
node verify.mjs  <node_modules/playwright のパス>   # 操作の検証（verify-result.json を書く）
node compare.mjs <node_modules/playwright のパス>   # 元案との比較（compare/ を書く）
```

## 未検証のこと

- Android 実機、WebView2、ソフトキーボードが出た状態での配置。
- スクリーンリーダーでの実際の読み上げ。確かめたのは読み上げ名の有無と内容だけである。
- ブラウザの文字だけ 200% の設定。確かめたのは、ページ全体の 200% に相当する 640×450 の viewport である。
- 背の低い窓（高さ 600px 未満）での編集面。
- 製品の `tests/ui/density.spec.mjs` による計測。この試作は製品の外にあるため、上の `compare.mjs` で同じ条件どうしを比べた。

## 機能・仕様として未接続のもの

元案の「後続実装検討事項」はそのまま残る（表記揺れの恒久統合、漢字の読み、最近の条件の保存、タグの分類、大規模照合の速度）。この案で加わるものは次のとおり。

- 追加した行に出す「再生待ちの N 番目」は、追加の応答に位置が要る。
- ⋯ の「再生の履歴」「ライブラリの設定」と、タブの「再生待ち」「プレイリスト」は画面を持たない。
- タグ編集は入力して Enter で行に加わるだけで、保存しない。

## 判断が残る点

1. **desktop で条件を1つ外すのが2手になった**。一行の語ごとに×を常設すると1手に戻せる。ただし条件の数だけ操作が増える。案としては、マウスでのホバー時だけ×を出す折衷もある。見つけにくくなるので採っていない。
2. **すべて/どれか の切替を編集面の中に入れた**。元案の見出しの切替は1手だったが、頻度は低いと判断した。
3. **narrow で上端にタブを置いた**。元案の narrow に無かった画面移動を足したもので、上端の 48px を使う。下端のタブバーにすると、再生バーと合わせて下が 2 段になる。
4. **ピンクを大幅に減らした**（3条件の desktop で 33,113 → 628 px²）。音楽文化の質感は、二色の印・版ずれした件数の数字・Dela Gothic の数字と追加先・紙の粒子に残した。それで足りるかはユーザーの目で判断してほしい。
5. desktop の右の追加先（312px）は残した。追加した位置が見えることを優先した。曲名の幅をさらに取りたいなら、ここを畳む選択肢がある。

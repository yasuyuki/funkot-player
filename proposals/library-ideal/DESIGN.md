# ライブラリの理想案

曲を探す画面を、管理ツールの列ではなく、一枚のセットリストとして設計した。聴く前に読むものは曲名で、探す条件は文として読み、足す先は画面に一箇所だけある。

実装の都合では削っていない。製品への組込みはここではない。

## 印象

Funkotの庫は、似た名前のリミックスが並ぶ場所である。快さはジャケットや波形ではなく、名前を読んで「これだ」と足すことにある。紙のセットリストを、青い灰色の床の上に一枚置く。条件が付くと、その言葉だけに朱の下線が付く。追加先は黄色い紙片が一枚。それ以外は墨と余白。

書体は Zen Kaku Gothic New ひとつ。走査の曲名は 700、判断で開いた曲名は 900、操作の言葉は 400。朱と黄は同時に主役にしない。画面の一番大きい文字は、条件がないときは検索欄、条件があるときはその文、曲を開いたときはその曲名。

行のあいだに罫線は引かない。ボタンは同じ静かな言葉で、中を塗った矩形は追加先の紙片だけに留める。

## 情報と操作

上端は三つの画面。ライブラリ、再生待ち、プレイリスト。再生の一行は下に残る。デッキは置かない。

ライブラリの頭は二つの文である。

- 追加先は、いま足す先。変えると、再生待ち、お気に入り、名前付きのリストから選ぶ。
- 再生元は、いま鳴っている供給元。言葉を押すとその画面へ行く。追加先と再生元は別で、同じ名前でも役割は分かれたまま残す。

曲名とアーティストの文字検索と、年・ジャンル・タグの条件は同時に使える。条件は文になる。

`年 2015 かつ タグ 日本人トラックメーカー かつ タグ アニソンremix`

`かつ` を押すと、その繋ぎだけが `または` になる。隣り合う `または` は一本の朱線を共有する。結果の行は「すべて一致」か「いずれかが一致」か「一致」で、混ざるときは「年が2015で、タグがアニソンremixか、タグがボカロ」のように読む。

年・ジャンル・タグは種類が名前に付く。`2015` は年でもタグでもあり得るので、候補は種類ごとに分け、同じ文字でも一つにまとめない。表記が違うタグ（アニソンremix と アニソンRemix）もまとめない。

候補は入力するまで並べない。一度に8件までで、該当件数を先に示す。試作の候補は1,500件の標本を含み、全件のスクロールはしない。実庫が数千件でも、この枠のまま文字を足して狭める。

条件が5件以上、または文字200%で3件以上のときは、文を「8条件をすべて満たす」と先頭二つの要約に畳む。曲の一覧は残る。条件の編集は左（狭い幅では上）に開き、外すと繋ぎの変更はそこでもできる。

曲名を押すと、その名前だけが大きくなる。アーティスト、年、長さ、同名のときのファイル名が続き、タグを見ることとお気に入りはそこから届く。追加は各行に常にある言葉で、大きさは曲名より小さい。ホバーしなくても読める。Enter でも追加する。

再生待ちには同じ曲を何度でも足せる。お気に入りは一度だけ。Funkotとして扱われていない曲は「追加できない」となり、開くと理由が出る。入っている曲は「追加先に1回入っている」と静かに書く。再生中は左の朱の棒と「再生中」で、年は消さない。

タグを直すときは、年の自動・指定・消去と、ジャンルとタグの追加と除去だけを出す。音源ファイルは変えない、とそこに書く。

0件のときは、各条件を外す言葉を出す。失敗のときは条件を残したまま「検索できなかった」と「もう一度探す」。探しているあいだは前の一覧を薄くし、件数の位置に「探している」と出す。

## 開き方

`proposals/library-ideal/index.html` をブラウザで開く。バックエンドはない。曲とタグは合成である。

幅は窓の大きさで見る。1280×900 と 412×915 を想定している。次のハッシュで状態を開ける。

| ハッシュ | 状態 |
| --- | --- |
| （なし） | ライブラリ |
| `#finder` | 年とタグの両方に「2015」がある候補 |
| `#results` | 年2015 かつ 日本人トラックメーカー かつ アニソンremix |
| `#judge` | その結果で、長い曲名を開いた状態 |
| `#or` | かつ と または が混ざる文 |
| `#eight` | 8条件。長いタグ名を含む |
| `#scale` | 標本タグ 1,500件からの候補 |
| `#empty` | 0件 |
| `#error` | 検索できなかった |
| `#loading` | 探している |
| `#blocked` | 追加できない曲を開いた状態 |
| `#zoom` | 文字200% |
| `#queue` | 再生待ち |
| `#added` | 追加した直後の文言 |

キーボードは、上下で曲を移動、Enterで追加、/で条件、Escapeで手前の層を閉じる。

再確認は、このリポジトリの Playwright が入った状態で `node proposals/library-ideal/verify.mjs`。画像は `shots/` に出る。

## 自分で画面を見た評価

デスクトップの通常状態では、最初に大きい検索欄、右に黄色い追加先、その下に曲名が来る。追加は右端の小さい言葉で、曲名の方が太い。同名の「オーバーレイ」「夜の回線」はファイル名が曲名の直下に出て、年と長さでも区別できる。再生中のオーバーレイは左の朱と「再生中」で、再生元は別の文のまま残る。

三つの条件を足した画面では、朱の下線が付いた条件の文が頭にあり、その下に「6曲がすべて一致」と6つの曲名が続く。追加先は今夜のセット、再生元は再生待ち、と二つが同時に読める。長い曲名を開くと、その行だけが黒く大きい名前になり、追加は同じ行の小さい言葉のままである。計測では、開いた曲名が32px、追加が14pxだった。

または に変えると、アニソンremix と ボカロが一本の朱線になり、下に「年が2015で、タグがアニソンremixか、タグがボカロ」と出る。かつ だけのときこの文は出さず、「すべて一致」で足りる。

8条件は頭が要約になり、編集欄に長いタグ「深夜のアニソンremixでベースだけ前に出す指定」が折返して出る。右には1曲と、その曲名が残る。欄の下の方の条件は欄の中をスクロールする。一覧は消えない。

候補欄は「該当は1,500件。8件まで表示する」を先に出し、標本を全件並べない。`2015` では年とタグが別の行になる。

0件は「一致する曲はない」と、外す条件が並ぶ。失敗は条件を残し、「検索できなかった」「条件はそのまま残っている」「もう一度探す」になる。

412pxでは、追加先が一番上、条件は折返し、曲名は左、追加は右に残る。長い曲名を開いた状態でも、名前の全体と「追加」が再生バーの上に見える。通常の一覧は、下端の再生バーに掛かる行が途中で切れる。これは一覧のスクロール境界で、上の曲名は欠けない。

文字200%では、三条件は「3条件をすべて満たす」と要約に畳まれ、追加先と再生元は読める。横にはみ出さない。ただし1280×900の第一画面では、要約と再生バーが縦を取り、曲名の一覧はほとんど次のスクロールに回る。条件の文字が切れて読めなくなる状態は、見たあとで要約に変えて解消した。

視線は、条件があるときは朱の文、曲を開いたときはその曲名、ないときは検索欄。追加先は黄色い一点で、行ごとの操作はそこに負けない。

## 操作の確認

Chromium で、説明ではなくクリックした。

- 条件を足すところから、年の2015、タグの日本人トラックメーカー、タグのアニソンremixを選び、結果は「6曲がすべて一致」になった。
- 最後の「かつ」を「または」にし、表示が「または」に変わり、件数も変わった。戻すと再びすべて一致になる。
- 長い曲名を開き、追加を押し、「再生待ちに追加した」と出た。再生待ちの一覧にその曲があった。
- 条件を一つ外した。
- 幅412で、年とアニソンremixを足し、先頭の曲を開いて追加し、「再生待ちに追加した「星を踏む」」と出た。

ページの例外はなかった。1280と412の各状態で、文書の横幅は窓の幅を超えなかった。axe の serious と critical は、ライブラリ、候補、結果、8条件、200%、狭い結果、狭い判断、の各画面で0件だった。最初の計測では、選択状態を `li` に `aria-selected` として付けていたのが違反だった。見たあとに外し、選択中は見えない文言で読むようにした。

## 試作の境界

描いている曲は50曲、候補の母数は年・ジャンル・タグに標本1,500件を足したもので、件数表示はその実数である。数万曲をDOMにはしていない。行の形と、候補を8件で止めることは、件数を増やしても変えない。

保存、スキャン、実ファイルのタグ解決はこの試作にない。年の矛盾・なし・不正、Funkotでないための追加拒否、お気に入りは一度、再生待ちは同じ曲を複数回、自動選曲は再生待ちの下に分けて動かせないこと、は画面上の意味として入れてある。

## 後続で実装するとき

デザインの目標は下げない。実装で別に扱うものは次である。

- 曲一覧は窓に入る分だけ描く
- 年・ジャンル・タグの索引に、この候補欄と同じ契約で問い合わせる。キーは `year:` `genre:` `custom:` のまま混ぜない
- 検索文字、条件、追加先、スクロール位置を画面遷移で残す
- 追加の拒否は実データの Funkot 判定に従う
- 年の自動・指定・消去と、埋め込みタグの抑制は、音源ファイルを書き換えずに保存する
- 再生待ちは項目を複数回追加でき、お気に入りは一曲につき一度
- 自動選曲の境界は、手動の項目を越えて並べ替えない

# Track tags

## Embedded metadata extraction

The library reads embedded metadata but never writes the music file.  Automatic
metadata is a candidate for the tag store; manual edits and exclusions are
resolved separately and remain authoritative.

`src-tauri/src/audio_metadata.rs` uses the Symphonia 0.6 metadata probe without
decoding audio.  It reads every metadata revision and both media-level and
per-track tag collections.  Symphonia 0.6's WAV reader parses RIFF INFO, but
its constructor retains only `opts.external_data.metadata`, discarding that
local result. WAV therefore has a narrow, read-only fallback for `INAM`,
`IART`, `ICRD`, and `IGNR`; malformed declared RIFF/INFO bounds are errors,
not tagless success. Each recognized INFO value has a 1 MiB resource-protection
budget: an in-bounds larger value is seeked past with a diagnostic, while a
malformed length is an error. A successful probe with no tags is still a
successful extraction; an I/O or parser error is reported to the scanner as an
error and must not be cached as a success.

| Format | Native fields read by Symphonia | Production-year treatment | Genre treatment |
| --- | --- | --- | --- |
| MP3 ID3v2.3 | `TYER` / `TYE`, `TCON` | recording candidate | preserve each native value |
| MP3 ID3v2.4 | `TDRC`, `TCON` | recording candidate | preserve each native value |
| FLAC | `DATE`, `YEAR`, `GENRE` Vorbis comments | generic candidate | preserve repeated `GENRE` values |
| Ogg Vorbis | `DATE`, `YEAR`, `GENRE` comments | generic candidate | preserve repeated `GENRE` values |
| M4A/MP4 | `©day`, `©gen` | `©day` is release-only and is not auto-adopted | preserve native value |
| WAV RIFF INFO | `INAM`, `IART`, `ICRD`, `IGNR` | recording candidate | preserve native value |

The source facts are kept as `raw_key`, `raw_value`, semantic kind and rank.
Only recording dates (rank 0) and general `DATE`/`YEAR` (rank 1) can produce a
production year.  Release and original dates remain visible candidates but are
never silently substituted.  The resolver accepts only `YYYY`, `YYYY-MM`,
`YYYY-MM-DD`, or an ISO date-time with a valid calendar date, `HH`, `HH:MM` or
`HH:MM:SS` time (optional fractional seconds), and optional `Z` or `±HH:MM`
offset.  Years before 1000 are invalid.  It
returns distinct `missing`, `invalid`, `future`, and same-rank `conflict`
states.  `TDAT`/`TDA` (day/month) and `TIME`/`TIM` (hour/minute) are never year
keys.

Genres are not split on punctuation, slash, or semicolon and are not
deduplicated at extraction time. Extraction uses the tag store's `Tag::new`
validation, so every accepted value is trimmed and NFC-normalized; an invalid
value produces one diagnostic without discarding its siblings.

### Synthetic fixture generation

Fixture audio is synthetic and contains no third-party song.  The set covers
MP3 ID3v2.3, MP3 ID3v2.4, FLAC, Ogg Vorbis, M4A, and WAV, plus tagless, invalid,
future, conflicting, release-only, original-only, and `TDAT`/`TIME` negative
cases.
Fixture generation is an offline preparation step; application tests open the
committed files read-only.  Tests record each file's bytes and mtime before
probing and assert that both remain unchanged afterwards.

The committed files are generated by
`scripts/generate-audio-metadata-fixtures.py` with imageio-ffmpeg 0.6.0's
bundled upstream FFmpeg 7.0.2 binary and Mutagen 1.48.1.  Both tools run from a
temporary environment; neither is a product dependency.  The generator uses
FFmpeg's `anullsrc` input, so every fixture is silent synthetic audio.  It
requires `FIXTURE_FFMPEG` to name that temporary executable and writes only to
`src-tauri/tests/fixtures/metadata/`.

imageio-ffmpeg is obtained from its PyPI manylinux wheel (BSD-2-Clause);
Mutagen is GPL-2.0-or-later; and the bundled FFmpeg binary remains subject to
its upstream license notices.  They are build-time fixture tools only.  The
fixtures contain generated silence and no copied recording.

| Fixture | Expected metadata outcome |
| --- | --- |
| `id3v23.mp3` | title/artist, recording year 2024, two native genres |
| `id3v24.mp3` | title/artist, recording date 2023-02-03, two native genres |
| `vorbis.flac` / `vorbis.ogg` | title/artist, generic date/year, repeated genres |
| `release-only.m4a` | title/artist and genre; `©day` retained as release-only |
| `riff-info.wav` | title/artist and RIFF INFO `ICRD`/`IGNR` |
| `future.mp3`, `invalid.flac`, `conflicting.flac` | distinct future, invalid, and conflict states |
| `original-only.mp3`, `id3-time-only.mp3`, `tagless.wav` | no adopted production year |

## Index migration and identity

`metadata_version = 1` marks successful extraction with this policy. An old
index entry with a matching mtime and size reuses its content hash and probes
metadata once, even if its old `tags_cached` flag was true. A current successful
entry, including a tagless file, needs no source open, hash, probe, or decode on
a warm scan. Failures remain retryable on the next ordinary scan and are shown
as errors; retained previous automatic values are not used as fresh tags.
The probe checks the fingerprint again before publishing its result.

The scan preserves `first_seen` and `added_order` for unchanged identity and
does not change history, labels, manual bars, or `track-tags.json`. Only a
committed index is published to the tag service. The existing content-hash and
mtime/size identity policy remains in use; it is not a new full-file integrity
guarantee. Future-year candidates are reevaluated from memory using the current
UTC year, without reopening audio.

## Internal UI contract

`list_track_tags` returns all current committed library rows in a memory
snapshot: `{ revision, ready, store_status, tracks }`. The opaque revision
includes the service session, committed library epoch, current year, and manual
store generation. A track includes nullable `content_hash`, `effective` tags
(`key`, `kind`, `value`, `origin`), `manual` year/additions/suppressions,
`auto_year`, `year_status`, `metadata_status`, raw `candidates`, and
`diagnostics`. Origin is `embedded`, `manual`, or `both`. Keys include their
kind, for example `year:2024`, `genre:funkot`, and `custom:2024`.

The typed definitions in `src/lib/tauri.ts` and their corresponding Rust
structures in `src-tauri/src/tag_service.rs` are the field-level contract.
`update_track_tags` receives this example through the Tauri `request` argument:

```json
{
  "targets": [{ "path": "/example/song.mp3", "expected_hash": "resolved-content-hash" }],
  "expected_revision": "opaque-revision-from-list",
  "patch": {
    "year_change": { "mode": "set", "value": 2024 },
    "add": [{ "kind": "custom", "value": "Practice" }],
    "remove": [{ "kind": "genre", "value": "Pop" }]
  }
}
```

Omitted year means no change; `auto` removes the manual override and `unset`
suppresses the automatic year. Add/remove are patches, not replacements. Every
target must still belong to the committed library and match its expected hash
and current lightweight fingerprint before any write. Duplicate hashes share
one manual record. The response is `{ snapshot, changed, no_op }`; both counts
refer to unique content hashes, not displayed paths. An unchanged transaction
does not rewrite the manual JSON or increment its generation.

Errors use stable codes: `invalid_input`, `identity_unavailable`,
`identity_changed`, `stale_revision`, `store_read_only`, `persist_failed`, and
`busy`. A batch error changes no target. A corrupt or unknown manual document
remains untouched and automatic metadata can still be viewed. Manual-store
recovery and backup boundaries are documented in [local data](local-data.md).

The frontend keeps tags separate from analysis rows. Request generations reject
late list responses; a scan reload during a save waits for the save, then reads
the committed state. Late analysis rows cannot replace a path's content hash or
resurrect a removed row. Tag list/update do not join the playback polling loop
and do not update queue, labels, history, or audio analysis.
